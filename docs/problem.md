# 问题定义（7 步流程 · 第一步）

## 1. 最终交付物

一个 iPhone 上可像多邻国一样刷的 GMAT 数学概念闪卡工具：英文概念词 → 中文概念映射，
Kai 在碎片时间（通勤、排队）打开即刷，10 天考试窗口内把高频概念词的「看题反应速度」练出来。

## 2. 硬约束

- **时间**：10 天后考试。工具必须今天/明天可用，词库 3 天内覆盖 GMAT Quant 高频概念
- **设备**：iPhone 使用（移动端优先、单手操作）；桌面浏览器也要能用（在家刷）
- **形式**：不分发、仅自用，零签名、零审核
- **内容质量**：词条必须是 GMAT 真实语境（题目里怎么出现，就怎么练），不是字典式背单词

## 3. 隐含要求

- 目标是「看题反应速度」，不是「背单词表」：练习项必须带 GMAT 风格题目例句，练的是题目语境
- 多邻国式体验：即时反馈、答错高频重见、无挫败感的短循环
- 进度自动保存，随时退出随时回来
- 内容更新能快速同步到手机（不缓存旧版）

## 4. 什么叫完成

Kai 任何碎片时间打开 → 不用思考「怎么用」直接开刷 → 一轮 2-5 分钟 → 错词当天反复出现 →
10 天后词库全部词至少见过 3 遍，错词进间隔重复队列 → 看到真题词汇秒反应中文概念。

## 5. 风险点（按严重度）

1. **词库质量与覆盖度**：核心价值。漏词/错译直接损害备考。必须覆盖六大专题高频概念，
   词条经 GMAT 真题语境校验
2. **手机拿不到更新**：PWA 缓存或 GitHub Pages 延迟导致旧词库一直在用
3. **交互摩擦**：需要说明书才能用=失败；打开必须直达刷题
4. **部署依赖**：GitHub Pages 需要 push（Kai 手动确认后执行）

## 6. 方案决策（第二步结论）

| 方案 | 结论 | 理由 |
|------|------|------|
| A. 原生 SwiftUI app | ❌ | 10 天窗口耗在 Xcode 签名/重签；每次更新词库要重装 |
| B. 单文件网页 + GitHub Pages（推荐） | ✅ | 零构建、随改随发、手机加主屏幕即全屏应用、无任何系统级需求 |
| C. Expo/RN 打包 | ❌ | 构建链复杂、签名问题一个不少，收益为零 |
